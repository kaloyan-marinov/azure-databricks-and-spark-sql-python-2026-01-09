# 179-3-2026-03-01-21-33-46-UTC-plus-1-best-practice.md

In general,
it's best practice to set up your own storage account
to use as your default «metastore» "storage root".



## Steps

1. create an ALDS Gen 2 account
   (by following the steps within `section-27/177-1-ADLS-Gen-2-set-up-and-data-upload.md`)

   call it `metastoreucwesteurope`

   therein,
   create a container called `metastore-westeurope`

2. create an «Access Connector for Azure Databricks» resource
   (by following the steps starting with `section-27/177-3-2026-03-01-18-40-29-create-an-access-connector-for-azure-databricks.png`)

   call it `metastoreucwesteurope-access-connector`

   (
   its `Resource ID` ended up being
   ```
   /subscriptions/6fb0aafb-5eb5-439c-9728-15bb1836570f/resourceGroups/rg-dataengineering-sandbox-westeurope/providers/Microsoft.Databricks/accessConnectors/metastoreucwesteurope-access-connector
   ```
   )

3. endow that resource with «Storage Blob Data Contributor» access to the storage account
   (by following `section-27/177-3-2026-03-01-18-53-33-endow-that-access-connector-with-the-relevant-access-to-the-storage-account.png`)

4. in Databricks, create a new «storage credential»
   (by following `section-27/177-3-2026-03-01-19-07-27-*.png`)

   call it `metastoreucwesteurope-credential`

5. in Databricks, create a new «external location»
   (by following `section-27/177-3-2026-03-01-19-08-05-*.png`)

   call it `metastoreucwesteurope-ext-location`
